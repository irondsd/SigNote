# About SigNote ✦

SigNote is an end-to-end encrypted notes app with three security tiers. Anything you mark as sensitive is encrypted in your browser before it leaves your device, so the server stores ciphertext it has no way to read.

The core idea is simple: **the app should not be able to read what you did not choose to show it**. You pick the security level for each note, and the keys stay with you — there is no password to reset, because there is nothing on the server that could undo the encryption.

---

## Three tiers of privacy 🔐

Not every note needs to be a secret. SigNote lets you choose the right privacy level for each piece of information:

| Tier | Name                     | Encryption                   | Best for                                 |
| ---- | ------------------------ | ---------------------------- | ---------------------------------------- |
| 1    | [Notes](/docs/notes)     | None                         | Everyday notes, to-dos, ideas            |
| 2    | [Secrets](/docs/secrets) | AES-GCM, shared session key  | Passwords, private info you access often |
| 3    | [Seals](/docs/seals)     | AES-GCM, unique per-note key | Your most sensitive data                 |

All tiers support **file attachments** — images render inline, other files appear as download cards. For Secrets and Seals, files are encrypted client-side before upload, just like note bodies. → [File uploads](/docs/file-uploads)

All encryption and decryption happens **in your browser**. The server only ever stores ciphertext — it never sees your plaintext note bodies or any key material capable of decrypting them.

---

## How identity works 🪪

There is no password anywhere in SigNote. Pick whichever way of proving who you are suits you:

- **Email code** — Enter your address, get a six-digit code, and you're in. Signing up and signing in are the same step.
- **Google** — One click, if you already have a Google account.
- **Sign-In with Ethereum (SIWE)** — Sign a message with your wallet. No email address is involved, so an account created this way is anonymous.
- **Passkeys** — Coming soon.

You can link several methods to the same account, so how you signed up doesn't lock you in.

Whichever you choose, it only governs access to your account. The passphrase that unlocks [Secrets](/docs/secrets) and [Seals](/docs/seals) is a separate thing, and no sign-in method can substitute for it.

→ Learn more in [Sign in](/docs/sign-in)

---

## How encryption works 🔑

For Secrets and Seals, encryption is unlocked with a passphrase you choose during setup. The passphrase is never stored — instead, SigNote derives a **Master Encryption Key (MEK)** by combining a passphrase-derived share with a server-side share. Neither side alone can reconstruct the key.

→ Deep dive in [Encryption](/docs/encryption)
